Analyze a GitHub repository

Paste the URL of a public GitHub repository. RepoBridge fetches its file tree, decides which files are worth reading and why, reads and normalises those it can, writes a summary grounded only in what it actually read, and records what happened at every stage — including what it skipped and what failed.

Try https://github.com/psf/requests if you want something to paste. A repository this size takes roughly ten seconds.

Public repositories only.

{# Two feedback channels on purpose. `analyze-status` is a polite live region and changes only at milestones, so a screen reader is not interrupted every second. `analyze-elapsed` ticks once a second and is hidden from assistive tech, because a running clock announced aloud is noise, not information. #}

{# An empty live region, not pre-written prose hidden with `hidden`. Before, this element shipped on every render carrying the words "Analysis failed." and "The attempt was still recorded" whether or not anything had failed, relying on the `hidden` attribute to keep it out of the accessibility tree -- which works, but is one stray `display` rule on `.notice` away from not working, and was never announced when it *did* appear because nothing marked it live. Now the container ships empty with `role="alert"`, the script fills it, and a screen reader hears the failure at the moment it happens. #}
